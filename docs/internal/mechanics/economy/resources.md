# Economy: Resources

This document defines the resource taxonomy, extraction model, storage model, movement rules, and credits layer for Wargame X. It establishes what resources exist, how the four raw resources and processed resources enter the economy, how credits function as the currency layer, and how they are moved between bases and players.

Quantitative values such as extraction rates, carrying capacity, processing recipes, and upkeep costs are defined in subsystem documents rather than here.

---

## Resource Taxonomy

Wargame X uses a multi-tier resource model with three tiers:

- **Raw resources** are generated by the world and extracted from map tiles.
- **Refined resources** are manufactured from raw resources in Tier 1 production buildings.
- **Advanced resources** are manufactured from refined resources in Tier 2 production buildings.

### Raw Resources

The confirmed base resource set is:

| Resource | Tier | Source | Primary role |
| --- | --- | --- | --- |
| Carbon | Raw | World extraction | Input to production, processing, and upkeep systems |
| Iron | Raw | World extraction | Input to production, processing, and upkeep systems |
| Crystal | Raw | World extraction | Input to advanced production, research, and upkeep systems |
| Oil | Raw | World extraction | Input to production, logistics, and upkeep systems |

Per-tile generation and regeneration rates are defined in [Resource Generation](../world/resource-generation.md).

### Processed Resources

Processed resources do not come directly from the world. They are created by converting raw materials inside production buildings. Processing behavior, recipe execution, and building-side constraints are defined in [Buildings: Production](../buildings/production.md).

#### Tier 1 — Refined Resources

These are produced from raw resources in Tier 1 production buildings (factories/refineries):

| Refined resource | Input A | Input B | Primary role |
|---|---|---|---|
| Steel | Iron | Carbon | Heavy construction, unit components |
| Electronics | Crystal | Iron | Advanced systems, tech production |
| Fuel | Oil | Carbon | Logistics, energy, combustion systems |

#### Tier 2 — Advanced Resources

These are produced from refined resources in Tier 2 production buildings:

| Advanced resource | Input A | Input B | Primary role |
|---|---|---|---|
| Composite | Steel | Electronics | High-tier units and structures |
| Plasma | Fuel | Crystal | Top-tier weapons and energy systems |

> **Design note:** The processing chain is confirmed at this tier depth (raw → refined → advanced). Crystal currently participates in two chains (electronics, plasma); its scope in the chain is left open for future expansion. Building tier requirements and exact processing costs are deferred to [Buildings: Production](../buildings/production.md).

### Credits

Credits are a special fifth resource that functions as the universal liquid currency of the economy.

Key properties that differ from raw and processed resources:

- Scope: Global per player (one shared pool, not per-base)
- Transfer: Instant - credits can be sent between players or used in transactions without physical transport
- Soft cap: There is no hard storage ceiling, but income from credits sources diminishes past a threshold (anti-snowball design)
- Generation sources (confirmed): Selling units, selling resources on markets, territory control income bonuses. Full source catalog is still open.
- Expenditure uses (confirmed direction): Market purchases (resources, units, services), diplomatic payments, tech shortcuts, unit recruitment fees. Full spend catalog is still open.
- Relationship to physical resources: Credits and physical resources are distinct economic rails. Physical resources require logistics; credits are the instant-settlement layer. Credits can be used in market transactions to buy physical resources, but the physical delivery of those resources still occurs through normal logistics.

> **Design note:** The full income formula, exact soft-cap threshold, and complete expenditure catalog are all intentionally deferred to [Economy: Income](./income.md).

## Extraction

Resources enter the economy through two extraction methods.

### 1. Building Extraction

A resource-extraction building placed on a tile extracts automatically from that tile each game tick. The building draws against that tile's resource generation and storage rules as defined in [Resource Generation](../world/resource-generation.md).

Key properties:

- Extraction is passive once the building is placed and operational.
- Output is tied to the specific tile under the building.
- Extracted resources are credited to the base that owns the building, subject to that base's storage limits.

### 2. Harvester Units

Specialized harvester units can extract resources from the tiles they occupy or visit and then carry those resources back to a base as cargo.

Key properties:

- Harvesters require physical movement between extraction points and deposit points.
- Harvested resources are not available for use until delivered to a base.
- Carry limits are determined by unit stats; see [Units: Stats](../units/stats.md).

### Coexistence Rules

Both extraction methods may operate on the same tile.

- A tile may host building-based extraction while also being worked by harvester units.
- The interaction is additive at the rules level unless another subsystem imposes a capacity or contention rule.
- Tile-side generation, regeneration, and depletion behavior remain governed by [Resource Generation](../world/resource-generation.md).

> **Design note:** This document confirms coexistence of extractors and harvesters on the same tile, but does not define any extraction-priority or contention formula. If such a rule is needed later, it should be added to the world resource-generation specification.

## Storage

Storage is distributed per base. WargameX does not use a single global player stockpile.

### Base-Local Storage

Each base maintains its own inventory for each resource.

- Resources stored at one base are not automatically available to another base.
- Production, upkeep, and outbound logistics consume from the local base inventory.
- Inter-base redistribution requires transport; see [Resource Movement (Logistics)](#resource-movement-logistics).

### Storage Capacity

Each base has a hard storage cap for each resource type. Capacity is determined by the warehouse or storage buildings constructed at that base.

- Storage limits apply per base, not per player.
- Capacity is a hard limit rather than a soft penalty threshold.
- Adding or upgrading storage infrastructure increases that base's capacity only.

### Full Storage Behavior

If a base has no remaining capacity for a resource, additional extraction for that resource at that base cannot be retained.

- There is no fallback global stockpile.
- A full base blocks further effective accumulation of that resource until capacity is freed or expanded.
- Building extraction and harvester delivery both resolve against the destination base's local storage state.

> **Design note:** Overflow handling is still provisional. Current intent is that resources beyond cap are lost, but this has not been explicitly confirmed as final. Until resolved, other documents should treat overflow as an open design question rather than a locked rule.

## Resource Movement (Logistics)

There is no instant transfer of physical (non-credit) resources in WargameX. All movement of physical resources requires transport across the map.

### Core Rules

- Forces carry resources between locations.
- Movement takes time based on normal map travel and force movement rules.
- Transporting forces can be intercepted by enemy forces.
- Unit carry capacity limits how much a force can move in a single trip.

Carry-capacity values belong in [Units: Stats](../units/stats.md). Map traversal behavior belongs in [Movement](../world/movement.md).

### Scope of Logistics

The physical-transport rule applies to all non-local resource movement:

- Inter-base transfers between a player's own bases
- Delivery of harvested resources back to a base
- Player-to-player trading
- Direct resource transfers between players

This makes logistics an exposed economic layer rather than an invisible background system.

## Trading

WargameX supports multiple trade channels, all of which depend on physical delivery rather than instant settlement.

### Trade Channels

| Channel | Description | Delivery model | Status |
| --- | --- | --- | --- |
| Public market | Open auction or exchange accessible to all players | Resources must be physically transported to the trade location | Detailed rules TBD |
| Private market | Negotiated trade between specific players | Resources must be physically transported to the trade location | Detailed rules TBD |
| Direct transfer | One player sends resources directly to another player | Resources are physically carried from sender to recipient | Confirmed concept |

### Shared Trade Constraints

- Trades do not bypass map distance.
- Trades are subject to travel time.
- Cargo can be intercepted before delivery.
- Force composition and unit carry capacity limit shipment size.

> **Design note:** Market structure, matching, pricing, escrow, and trade-location rules are still open. This document only fixes the delivery constraint: resources must move physically through the world before a trade completes.

## Consumption and Upkeep

Resources are consumed continuously by three confirmed upkeep domains:

- Units
- Buildings
- Active research

Upkeep is resolved from the relevant local storage source defined by the upkeep system.

- A base pays the upkeep for buildings, research, and units stationed there.
- Units operating away from base pay from their own carried cargo.
- One base's surplus does not automatically cover another base's deficit.
- A base that cannot pay full upkeep enters a deficit state and degrades over time.

Deficit consequences and timing are defined in [Economy: Upkeep](./upkeep.md).

> **Design note:** This document confirms the upkeep domains and the local-source payment model, but not the exact payment order, grace period, or attrition formula. Those belong in the dedicated upkeep specification.

## System Summary

| Topic | Confirmed rule |
| --- | --- |
| Base resource set | Carbon, Iron, Crystal, Oil |
| Resource tiers | Raw (4), Refined (3), Advanced (2), plus Credits - 10 total |
| Processing chain depth | Three tiers (raw → refined → advanced) |
| Credits scope | Global per player |
| Credits transfer | Instant (no physical movement required) |
| Credits cap | Soft cap (income diminishes above threshold) |
| Credits sources | Markets, unit sales, territory income bonuses (full catalog TBD) |
| Credits uses | Purchases, diplomacy, tech, recruitment (full catalog TBD) |
| Extraction methods | Building extraction and harvester units |
| Shared-tile extraction | Both methods can coexist on the same tile |
| Storage model | Per-base, distributed storage |
| Global stockpile | None |
| Capacity model | Hard per-resource cap per base |
| Overflow over cap | Provisionally lost; final rule still open |
| Resource transfer | Always physical, never instant |
| Trading | Public market, private market, and direct transfer |
| Trade delivery | Physical transport with travel time and interception risk |
| Upkeep domains | Units, buildings, active research |
| Upkeep scope | Paid from local base storage or unit-carried cargo, depending on domain/state |

This specification is complete for the confirmed structural rules of the resource system. Quantitative balance, processed-resource expansion, trade-market mechanics, and overflow finalization remain intentionally deferred to their dedicated subsystem documents.
